## Still open

- **`cycle.html:1917-1919` — recovery mode can never be entered a second time.** `if (!blank && !S.p.recoveryOff) { … if (started.length) S.p.recoveryOff = false; }` only assigns `false` when `recoveryOff` is already falsy, so it is a no-op, and once "Start estimating again" has set `recoveryOff = true` (:1869, persisted) `recoveryDate()` returns null forever (:419). Confirmed: logged Miscarriage on Sep 8 → recovery card appeared; pressed `end-recovery` → card gone, `LKStore.get('lk_mcProfile').recoveryOff === true`; then logged **Abortion** on Sep 9 and saved — the event is stored (`events: ["abortion"]`) but no recovery card appears and predictions keep running. The fix is `if (started.length) S.p.recoveryOff = false;` outside the `!S.p.recoveryOff` guard.
- **`cycle.html:1117-1182` (`paintOf`/`monthGrid`) — discreet mode does not reach the calendar.** The ring deliberately greys its arcs in discreet mode because "four named hues are the phase, told in colour" (:583-585), but the month grid paints the same information and does not: in `?state=discreet` + calendar toggle, 17 September cells still carry `cyccal-fert` / `cyccal-ov` / `cyccal-pms` / `cyccal-pred` classes, with the key hidden (:1184) so the colours are unexplained rather than absent. Someone handed the phone sees the fertile and PMS windows.
- **`cycle.html:601-602` — the ring's slider values contradict its own label when overdue.** In `?state=overdue` the centre and `aria-valuetext` say "Day 47 of an estimated 28 day cycle" while `aria-valuenow="28"` and `aria-valuemax="28"`, so a screen-reader user stepping the slider is told a different day number from the one on screen. Minor, but it is a claim the data does not support.
